# Advisory Bedrock schemas

These unmodified JSON Schema draft-07 files come from [Blockception/Minecraft-bedrock-json-schemas](https://github.com/Blockception/Minecraft-bedrock-json-schemas/tree/e04436c149ab2f9592e2b623aac9e19f0c6b2849) at commit `e04436c149ab2f9592e2b623aac9e19f0c6b2849`. The upstream BSD license is included here. The advisory fixture requires generated documents in eight behavior-pack families: blocks, entities, feature rules, features, items, loot tables, recipes, and spawn rules.

Two schema exceptions are machine-matched by `exceptions.json`: this schema revision omits `minecraft:recipe_smithing_trim`, and its untyped tag branch makes direct string ingredients fail the `oneOf` check in smithing-transform recipes. Both shapes are present in the pinned Mojang samples at [smithing_armor_trim.json](https://github.com/Mojang/bedrock-samples/blob/921fafb05c93abeae56c2f2868cd8f942bdbcc0f/behavior_pack/recipes/smithing_armor_trim.json) and [smithing_netherite_sword.json](https://github.com/Mojang/bedrock-samples/blob/921fafb05c93abeae56c2f2868cd8f942bdbcc0f/behavior_pack/recipes/smithing_netherite_sword.json). The linter requires each exception to occur the expected number of times, so a changed output shape or stale exception fails the advisory check.

Run `scripts/lint-bedrock-schemas.sh` to compile a fresh aggregate fixture and validate all eight families. Run `scripts/refresh-vanilla-catalog.sh --check` to compare the catalog against Mojang's pinned sample data. CI runs both checks; neither replaces exact Mojang-sample assertions or physical-device acceptance.
