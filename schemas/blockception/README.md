# Advisory Bedrock schemas

These JSON Schema draft-07 snapshots come from [Blockception/Minecraft-bedrock-json-schemas](https://github.com/Blockception/Minecraft-bedrock-json-schemas/tree/e04436c149ab2f9592e2b623aac9e19f0c6b2849) at commit `e04436c149ab2f9592e2b623aac9e19f0c6b2849`. The local entity schema adds the missing `type: object` constraint for the entity description. The upstream BSD license is included here. The advisory fixture requires generated documents in eight behavior-pack families: blocks, entities, feature rules, features, items, loot tables, recipes, and spawn rules.

Three schema exceptions are machine-matched by `exceptions.json`: this schema revision omits `minecraft:recipe_smithing_trim`; its untyped tag branch makes direct string ingredients fail the `oneOf` check in smithing-transform recipes; and it omits the transform `template` property. These shapes are present in the pinned Mojang samples at [smithing_armor_trim.json](https://github.com/Mojang/bedrock-samples/blob/921fafb05c93abeae56c2f2868cd8f942bdbcc0f/behavior_pack/recipes/smithing_armor_trim.json) and [smithing_netherite_sword.json](https://github.com/Mojang/bedrock-samples/blob/921fafb05c93abeae56c2f2868cd8f942bdbcc0f/behavior_pack/recipes/smithing_netherite_sword.json). The exception counts detect changes to those matched validation errors, not every possible output-shape change; exact sample-backed output structures are asserted in compiler tests.

Run `python3 -m pip install jsonschema==4.25.1` and then `scripts/lint-bedrock-schemas.sh` to compile a fresh aggregate fixture and validate all eight families. Run `scripts/refresh-vanilla-catalog.sh --check` to compare the catalog against Mojang's pinned sample data. CI runs both checks and the Python regression tests; neither replaces exact Mojang-sample assertions or physical-device acceptance.
